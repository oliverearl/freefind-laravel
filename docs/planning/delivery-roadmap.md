# Delivery roadmap and quality plan

## Delivery strategy

Build vertical internal slices, but do not publish partial `0.x` releases. Generated markup and XML fixtures are the contracts; Blade components sit on top only after those contracts are stable. The first published package is the complete `1.0.0`.

Status: configuration, opt-in spider context, crawler-markup renderer/directives, hosted search UI, conservative route annotation middleware, sequential-request isolation coverage, typed XML request core/bounded transport, secure typed response parsing, the explicit user-initiated XML client call, semantic unstyled XML result components, and immutable simple-query builder ergonomics are implemented. Remote contract fixture acquisition remains pending; no live service is used by normal tests.

Next: add package fake/assertion support and manually gated live-contract coverage; keep remote contract acquisition pending until an operator supplies a subscribed account/query.

## Milestone 0 — decisions and contract fixtures

Goal: remove ambiguities that could force public API churn.

Work:

- decide the open product questions in [`decisions-and-open-questions.md`](decisions-and-open-questions.md);
- capture representative hosted-form HTML generated by the current FreeFind Control Center;
- capture XML fixtures for success, zero results, pagination, spelling suggestion, auto-OR, every status code available, optional/missing fields, and malformed payloads;
- verify whether response highlight markup is escaped text, CDATA, nested XML, or a mixture;
- verify `noFollowQueries` versus `noQueries` on a disposable account;
- confirm current FreeFind plan/terms for XML use and result reuse before adding any caching;
- select and declare the XML extension, and replace the insufficient contracts-only runtime assumption with an explicit supported `laravel/framework` requirement;
- configure the available subscribed account for manually invoked, group-gated live contract tests without committing its site ID or search data;
- record fixtures' acquisition date and redact queries/site IDs where appropriate.

Exit criteria:

- unresolved service behavior is isolated behind an interface or explicitly deferred;
- fixture provenance is recorded;
- no production test depends on FreeFind availability.

## Milestone 1 — configuration and rendering core

Goal: establish stable primitives with no HTTP behavior.

Work:

- introduce a string site ID and validated default Page Search account;
- add immutable annotation value objects and centralized renderer;
- add comment/meta escaping and absolute-URL validation;
- register non-deprecated page and fragment Blade directives;
- add the `@freefindHead` annotation collector hook;
- publish revised configuration.

Exit criteria:

- exact-string tests cover every supported annotation;
- invalid comments, attributes, URLs, dates, counts, and mismatched regions fail clearly;
- every non-deprecated Page Search-specific FreeFind tag in the downloaded reference is supported or documented as intentionally delegated to normal HTML/SEO tooling;
- rendering performs no I/O and has no request-global side effects.

Internal checkpoint only; do not publish.

## Milestone 2 — hosted search UI

Goal: provide the useful free-account integration.

Work:

- implement hosted search request encoder and URL value objects;
- create accessible unstyled search-form component;
- support documented sections, languages, `nsb`, and extended CSS fields;
- add slots/attributes and publishable view;
- document FreeFind-hosted template constraints and Control Center setup;
- add browser/feature tests for query preservation, labels, keyboard submission, repeated sections, and HTML escaping.

Exit criteria:

- a blank Testbench application can render and submit a working form from config alone;
- all generated endpoints use HTTPS;
- protocol fields cannot be overwritten accidentally through an attribute bag;
- component output passes an automated HTML/accessibility sanity check.

Internal checkpoint only; do not publish.

## Milestone 3 — spider context and middleware hardening

Goal: replace proof-of-concept global mutations with request-safe integration.

Work:

- extract `SpiderDetector` and request-scoped `SpiderContext`;
- register middleware aliases and choose explicit global opt-in behavior;
- set cache policy on the returned response object;
- implement annotation middleware through `@freefindHead` collection first;
- test middleware order with Laravel 11 and 12;
- test sequential requests in one process to detect Octane-style state leakage;
- remove or quarantine session-driver mutation until isolation is proven;
- document that user-agent detection never authorizes access.

Exit criteria:

- browser requests after a spider request see their original session/cache configuration;
- non-HTML, streamed, redirect, exception, and binary responses remain valid;
- stricter existing cache headers are preserved by default;
- global middleware is not silently forced upon all package consumers.

Internal checkpoint only; do not publish.

## Milestone 4 — typed XML client

Goal: support bespoke results pages for subscribed page-search accounts.

Work:

- implement query types, enums, options, request builder, and repeated-key encoder;
- add injected Laravel HTTP transport with bounds/timeouts and limited transient retry;
- add secure tolerant XML parser;
- model response counts, sections, spell suggestion, auto-OR, results, date, target, and local pagination;
- map service statuses and transport/parser errors into the documented exception taxonomy;
- add plain-text normalization and preserve explicitly named raw highlighted fields as a first-class `1.0.0` feature;
- add semantic unstyled result-list, result-item, pagination, spelling-suggestion, and empty-state Blade components without registering a route/controller;
- add `Http::fake()` support and package fake/assertions;
- write subscriber restriction and human-query-only documentation.

Exit criteria:

- every applicable XML request parameter and response tag is covered by tests;
- repeated sections serialize exactly as FreeFind requires;
- XXE/network entity tests, oversized body tests, malformed XML tests, unsafe URL tests, and remote-HTML escaping tests pass;
- no API path exposes DTD, XSLT, XML web search, DataSearch, scheduler, or bulk search;
- logs and exception messages do not expose raw queries/results by default.

Internal checkpoint only; do not publish.

## Milestone 5 — documentation and migration experience

Goal: make the package adoptable without reading FreeFind's legacy manual first.

Work:

- replace the generated package README with installation, hosted form, crawler annotations, XML client, raw-highlight handling, security, and troubleshooting guides;
- add a migration table from raw FreeFind snippets to package directives;
- document all Control Center steps that the package cannot automate;
- document comment-preserving CDN/minifier settings and the re-index feedback loop;
- explain that Page Search and DataSearch require two ordinary FreeFind accounts with separate credentials/site IDs, and that no DataSearch functionality is part of `1.0.0`;
- remove scaffold-era examples rather than documenting compatibility with unpublished exploratory APIs;
- add complete PHPDoc and static-analysis generics.

Exit criteria:

- a clean application can follow each guide successfully;
- every public symbol is documented and tested;
- caveats appear next to the relevant examples, not only in a security appendix;
- package metadata and README no longer contain scaffold placeholders or irrelevant migration instructions.

Internal checkpoint only; do not publish.

## Milestone 6 — release candidate and 1.0

Goal: validate the complete package under supported runtimes.

Work:

- run the matrix on PHP 8.4 with Laravel 11 and 12;
- run Pint, Larastan at the agreed level, Pest, architecture tests, and dependency audit;
- run the manually enabled `live-contract` Pest group against the available subscribed Page Search account using an operator-supplied query; never run this group in normal or scheduled CI;
- test PHP-FPM-like and Octane-like request lifecycles;
- perform a final API naming/BC review;
- confirm licence and attribution requirements for fixtures and generated FreeFind output;
- publish an upgrade policy and support boundary for remote FreeFind changes.

Exit criteria:

- no known high-risk security issue;
- no unresolved public API ambiguity;
- live contract results match local fixtures or differences are handled/documented;
- the complete agreed `1.0.0` scope and later backlog are explicit.

## Post-1.0 candidates

Prioritize from real usage rather than implementing every historical FreeFind feature:

- highlight sanitizer and rich result components;
- diagnostics command and local indexability inspector;
- log import/parser if FreeFind offers a stable export;
- integrations for common SEO metadata packages;
- custom template exporter with byte-size and absolute-link linting;
- a complete DataSearch module—second regular-account configuration, mode/category/listing directives, and generated-item linting—using the available DataSearch account to validate behavior before its API is designed;
- Laravel Scout bridge only if its semantics can honor user-initiated-query restrictions without pretending FreeFind is a mutable Scout engine.

Package-owned controllers/routes, Control Center scraping, automated indexing, and password-protected-content helpers should remain out of scope unless concrete consumer evidence or safer supported FreeFind interfaces justify them.

## Testing matrix

### Unit tests

- annotation value validation and exact serialization;
- comment/quote/control-character escaping;
- date and URL normalization;
- query request invariants and pair encoding;
- response scalar parsing and status mapping;
- safe-text extraction and target policy;
- pagination offset math at boundaries.

### Feature tests

- directive compilation and nested loops/conditionals;
- component rendering and published-view override;
- missing/default account configuration and the reserved future account-resolver seam;
- middleware HTML eligibility, ordering, cache behavior, and state isolation;
- service container/facade resolution;
- config caching and package discovery.

### Security tests

- comment breakout attempts (`--`, `-->`, quotes, control bytes);
- XSS-bearing keyword, title, description, image, map, and what's-new data;
- `javascript:`, `data:`, protocol-relative, credential-bearing, and malformed URLs;
- XML external entity, entity expansion, DTD, XInclude, huge payload, deep/wide element sets;
- redirect to insecure/unexpected origins;
- query/result redaction in logs and exceptions;
- spoofed spider user agent does not alter authorization outcome;
- consecutive worker requests do not inherit spider state.

### Fixture/contract tests

- one fixture per documented XML shape and error status;
- form/query snapshots checked against captured FreeFind examples;
- a `live-contract` Pest group excluded from normal and scheduled CI, requiring an explicit enable flag, the subscribed account's environment configuration, and a query entered for that run by the operator;
- fixture updates reviewed as protocol changes, not ordinary snapshots.

### Compatibility and quality gates

- PHP 8.4;
- lowest and latest dependency sets for Laravel 11 and 12 where Composer permits;
- Pest suite, Laravel Pint, Larastan, package architecture/security presets;
- no network in normal CI;
- no new runtime dependency without a security/maintenance justification.

## Definition of done for each feature

A feature is done only when:

1. its source contract is linked or its inferred nature is stated;
2. valid and invalid inputs are represented in tests;
3. Blade/PHP usage is documented;
4. network, remote-change, security, and re-index implications are documented where relevant;
5. behavior works on both supported Laravel majors;
6. public API names avoid leaking FreeFind abbreviations unless they are protocol-level;
7. it does not create state leakage under a long-running worker.

## Principal delivery risks

| Risk | Impact | Mitigation |
|---|---|---|
| FreeFind changes or removes an undocumented legacy behavior. | Generated markup or XML parsing stops working. | Contract fixtures, tolerant parser, dated docs, opt-in live smoke tests, small protocol adapters. |
| The XML feature is developed without a subscribed test account. | “Correct” implementation may differ from live payloads. | Treat live fixture acquisition as Milestone 0; keep uncertain behavior behind interfaces. |
| Comments are removed by optimization infrastructure. | Pages silently lose crawl annotations. | Installation warning, diagnostic tooling, production-response integration test guidance. |
| User-agent state leaks under Octane. | Browser sessions/caching behave incorrectly after crawls. | Request-scoped objects, no persistent config mutation, sequential-request tests. |
| Remote result markup produces XSS. | Bespoke results page compromise. | Plain text by default, URL validation, no automatic `HtmlString`, security fixtures. |
| Package implies private-content safety. | Search snippets leak protected content. | Never authorize by user agent; prominent warning; no convenience bypass middleware. |
| Too many directives create an incoherent API. | Maintenance and learning burden. | Central annotation objects, consistent naming, only non-deprecated tags, common-path docs first. |
